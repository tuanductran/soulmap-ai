# SoulMap domain index

## Use When

- The request clearly belongs to a SoulMap knowledge domain.
- Meta orchestration has already established the response posture.

## Don't Use When

- Safety, crisis, scope, brand, voice, or runtime integration is primary.
- A domain is not yet clear.

## Workflow

1. Identify the primary domain.
2. Open exactly one domain router below.
3. Follow that router to the canonical knowledge files.
4. Return to meta orchestration for synthesis and safety validation.

## Rules

- Domain routers are navigation layers, not duplicate knowledge bases.
- Keep implementation details out of domain knowledge.

## Examples

- Inner conflict or grief -> [inner-work](inner-work/SKILL.md).
- Relationship patterns -> [relationships](relationships/SKILL.md).
- Spiritual discernment -> [spirituality](spirituality/SKILL.md).

## Edge Cases

- If several domains are present, choose the one selected by orchestration.
- If safety changes the response mode, safety takes precedence.
