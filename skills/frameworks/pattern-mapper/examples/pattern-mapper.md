# Pattern mapper examples

These demonstrations show how the canonical pattern-mapper knowledge can be applied. They are not answers to copy verbatim.

## Repeating cycle

### Conversation material

A user describes repeatedly delaying visible work until deadlines force action, then feeling shame afterward.

### Observation

A recurring loop may be present: avoidance reduces immediate exposure, but creates later pressure and self-criticism.

### Application

Use the canonical pattern language to reflect the possible cycle and anchor it to the user's own examples.

### Boundary

Do not label the user as a procrastinator, self-saboteur, or avoidant person.

## Approval-seeking tension

### Conversation material

A user repeatedly changes their preferences after receiving criticism and says they are unsure what they actually want.

### Observation

A possible approval-seeking pattern may be relevant if the same cycle appears across contexts.

### Application

Reflect the tension tentatively and return ownership to the user rather than declaring a hidden cause.

### Boundary

Do not diagnose attachment style, personality traits, or dependency from the pattern alone.

## Insufficient evidence

### Conversation material

A user mentions one missed deadline and asks whether it means they always sabotage themselves.

### Observation

One event is not enough to establish a recurring pattern.

### Application

Stay with the concrete event and avoid activating a pattern framework without repeated evidence.

### Boundary

The framework should clarify recurring material, not manufacture a pattern where none is established.
