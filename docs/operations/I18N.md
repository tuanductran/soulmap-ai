# SoulMap AI i18n

SoulMap website dùng **JSON catalog theo từng locale**, được load bằng Python và giữ nguyên public adapter `messages_for()`, `translate()` và `messages_json()`. Layout tiếp tục inject một JSON payload inert vào DOM; không có runtime API, JavaScript translation loader hoặc trạng thái locale toàn cục.

## Source of truth

Các bản dịch nằm trong:

| File | Locale | Vai trò |
| --- | --- | --- |
| [`src/soulmap/web/locales/en.json`](../../src/soulmap/web/locales/en.json) | `en` | English fallback và catalog key chuẩn |
| [`src/soulmap/web/locales/vi.json`](../../src/soulmap/web/locales/vi.json) | `vi` | Bản dịch tiếng Việt |
| [`src/soulmap/web/locales/ko.json`](../../src/soulmap/web/locales/ko.json) | `ko` | Bản dịch tiếng Hàn |
| [`src/soulmap/web/i18n.py`](../../src/soulmap/web/i18n.py) | - | Typed loader, fallback, escaping và JSON serialization |

English định nghĩa tập key chuẩn. Import-time validation yêu cầu mọi locale có đúng cùng tập key và mọi giá trị đều là chuỗi. Khi thêm key, cập nhật cả ba JSON files trong cùng một thay đổi và chạy test i18n trước khi sửa renderer.

## Safe maintenance workflow

Trước khi commit nội dung mới, chạy:

```bash
uv run pytest tests/unit/test_web_i18n.py tests/unit/test_web_server.py -q
uv run ruff check src/soulmap/web/i18n.py tests/unit/test_web_i18n.py
uv run pyright src/soulmap/web/i18n.py tests/unit/test_web_i18n.py
```

Sau đó chạy full validation và static verifier theo [`docs/engineering/DEV.md`](../engineering/DEV.md). Không đặt HTML hoặc JavaScript vào catalog. `messages_json()` vẫn phải escape các delimiter `<`, `>` và `&` trước khi chèn payload vào thẻ `application/json`.

## Package audit decision

Audit ngày 21 tháng 8 năm 2026 đã xem xét Python standard-library `gettext`, Babel, Project Fluent, `flufl.i18n`, `python-i18n` và `i18nice`. Kết luận là **không thêm runtime i18n package trong migration này**.

| Candidate | Audit result |
| --- | --- |
| [`gettext`](https://docs.python.org/3/library/gettext.html) | Mature và có sẵn trong Python, nhưng dùng PO/MO catalogs và cần quy trình extract/compile; không phải drop-in JSON registry. |
| [`Babel`](https://pypi.org/project/Babel/) | Ổn định, BSD-3-Clause, cung cấp CLDR và tooling cho gettext; phù hợp làm development tooling nếu dự án chuyển sang PO/MO, chưa phù hợp làm runtime JSON adapter hiện tại. |
| [`python-fluent`](https://projectfluent.org/python-fluent/) | Có runtime và syntax expressive, nhưng thêm message language/parser mới trong khi website chỉ cần key/value tĩnh cho ba locale. |
| [`flufl.i18n`](https://pypi.org/project/flufl.i18n/) | Mature và dùng gettext-style context; format không khớp JSON-in-DOM contract. |
| [`python-i18n`](https://pypi.org/project/python-i18n/) | Có JSON/YAML, fallback và pluralization nhưng bản PyPI 0.3.9 cũ, trạng thái Beta và maintenance nhỏ. |
| [`i18nice`](https://pypi.org/project/i18nice/) | Gần format hiện tại nhất, hỗ trợ JSON/YAML, namespace và fallback; tuy nhiên dùng mutable global configuration và có maintenance footprint nhỏ, nên không cải thiện đủ so với loader typed, deterministic của repository. |

Babel và gettext có thể được xem xét trong một PR tương lai nếu SoulMap cần plural/context phức tạp, nhiều contributor dịch thuật hoặc quy trình PO/MO chuyên nghiệp. Khi đó phải có migration plan riêng và không trộn với static-site refactor.

## Design constraints

Nguồn JSON này không thay đổi public Skills, không xuất hiện trong các Skill bundles và không đưa thông tin nội bộ vào nội dung website. Python chỉ đọc catalog lúc build/serve, sau đó render toàn bộ nội dung locale cần thiết vào HTML static. Cách này giữ simultaneous locale export, Git diff dễ review hơn và tránh process-global `setlocale()`.
