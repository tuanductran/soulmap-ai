# Safety enforcement matrix

This matrix turns SoulMap AI safety claims into an evidence-backed map. For a
narrative explanation of how these layers fit together end to end, request
flow, execution order, and ownership boundaries, see
[`docs/engineering/safety-architecture.md`](safety-architecture.md). This
document stays focused on evidence per rule and does not restate that
walkthrough.

Status values:

- `enforced`: explicitly enforced in code and covered by tests or evals
- `partial`: some enforcement exists, but the remaining coverage is achievable
  inside this package and simply has not been built yet
- `bounded`: runtime enforcement and eval coverage exist inside the package;
  the remaining gap is generated wording (or a judgment call about whether
  generated wording competently fulfills the rule), which is the deployed AI
  surface's job, not Python's, per
  [`docs/engineering/known-limitations.md`](known-limitations.md), "AI
  response generation". Not a lower grade than `partial`, a different kind of
  gap that no amount of new Python code closes
- `guidance-only`: documented doctrine with no direct code enforcement yet

## How to use this matrix

- Treat `enforced` rows as claims backed by code plus tests or evals.
- Treat `partial` rows as active hardening targets achievable inside this package.
  The gap note says what is missing and why it is buildable here.
- Treat `bounded` rows as at their ceiling inside this package. The gap note names
  the deployed AI surface that completes the wording and the eval that verifies it
  there; no new Python code closes a `bounded` row.
- Treat `guidance-only` rows as doctrine that still needs explicit implementation or
  response-level verification before being described elsewhere as enforced.

A row moves from `bounded` back toward `partial` only if the package's own
architecture changes, for example if a future ADR authorizes a new class of
runtime validator. Reclassifying a row without such a change would misstate what
the code can do; see
[`docs/engineering/known-limitations.md`](known-limitations.md) before proposing one.
